# Ревью

1. Прочитай `docs/REVIEW.md`.
2. Смотри diff ветки относительно `main`, не весь репозиторий.
3. Пиши замечания по делу: баг, дыра, нарушение паттерна проекта. Стиль без влияния на поведение не раздувай.
4. Lock-файлы и сгенерированные миграции не ревьюй построчно, если задача их не меняла намеренно.
